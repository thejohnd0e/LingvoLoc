# Phase 6 DOCX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add recoverable DOCX translation and safe package-preserving export to the existing Documents workflow.

**Architecture:** Parse only supported semantic paragraphs from `word/document.xml`, persist them through the existing format-neutral job pipeline, and rewrite that one XML part during export while raw-copying all other ZIP entries. Persist explicit diagnostics for unsupported stories and ambiguous run boundaries, and expose them through the existing job view.

**Tech Stack:** Rust 2021, Tauri 2 commands, `zip` 2.4, `quick-xml` 0.42, SQLite/rusqlite, React/Vite/strict TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-29-docx-phase6-design.md`

## Global Constraints

- Preserve all unrelated and user-authored changes in the dirty worktree.
- Do not change TXT behavior, extension APIs, ordinary history, runtime settings, or global translation prompts.
- Translate only supported paragraphs in `word/document.xml`; preserve unsupported stories and constructs unchanged and report them.
- Never replace a source or existing output file.
- Do not expand the phase to EPUB, FB2, or PDF.
- Do not commit, publish, change versions, or package release artifacts without separate user instruction.
- Keep DOCX package/XML code outside the existing large `commands.rs` and `DocumentsPanel.tsx` files.
